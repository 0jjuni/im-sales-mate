# 은행 펀드 정보 수집

iM뱅크 펀드검색 목록과 상품 상세, 상세 화면 안에 연결된 펀드 정보 표를 저장했다. 운용사 사이트를 따로 검색하거나 PDF를 내려받는 작업은 포함하지 않았다.

2026년 9월 9일 기준 목록의 246개 클래스 상품을 수집했다. 240개는 하단 8개 탭의 표를 모두 읽었고, 6개는 일부 탭에서 HTTP 500 오류가 반복돼 정상 탭만 보존했다. 해당 탭에는 `status: "unavailable"`과 오류를 기록했다. 오류 상태는 빈 값이나 수익률 0으로 표시하면 안 된다.

기존 데모 248개 중 246개는 클래스까지 대조해 대응표에 기록했다. 한화중국본토 A-e·C-e 두 클래스는 현재 은행 목록에서 찾지 못했다. 기존 카탈로그에서는 삭제하지 않았다.

## 저장 위치

- `public/data/wealth-bank/index.json`: 수집 대상 상품 코드와 정식 상품명
- `public/data/wealth-bank/{상품코드}.json`: 은행 상품설명과 하단 정보
- `public/data/wealth-bank/catalogue-map.json`: 기존 데모 상품 ID와 은행 상품 코드의 대응표
- `public/data/wealth-bank/collection-report.json`: 전체 파일 검증 결과와 열리지 않은 탭 목록

상품별 JSON은 해당 파일 하나만 읽으면 된다. 예를 들어 대응표의 `mapping[product.id]`로 은행 코드를 찾은 뒤 `/data/wealth-bank/{코드}.json`을 읽는다. 파일을 앱과 함께 배포하므로 실행 중 외부 은행 사이트에 접속할 필요가 없다. 이번 변경은 자료 수집과 대응표까지이며, 기존 화면의 예시 차트와 카탈로그 수치는 바꾸지 않았다.

## 수집 범위

은행 상품설명에는 투자대상, 위험등급, 수수료, 총보수, 상품별 투자위험을 담았다. 하단은 상품안내·펀드개요·일별기준가·차트분석·성과분석·위험분석·포트폴리오분석·보유내역의 8개 탭이다.

`bank.summary`는 상품 상단 설명이고, `bank.tables`와 각 `sections[].tables`는 표의 셀을 행 순서대로 저장한다. 셀의 `rowSpan`, `colSpan`, `header`도 보존했다. 은행 원문의 표 제목에는 내용과 맞지 않는 접근성 설명이 일부 있으므로 화면 제목으로 그대로 사용하지 않는 편이 좋다.

기준일은 원문 제목과 셀에 남아 있다. 수집 시각인 `retrievedAt`과 자료 기준일은 다르다. 수익률·보유내역의 기준일도 서로 다를 수 있으므로 화면에서는 각각 표시해야 한다.

차트 그림, 이미지로 표시한 등급, 마우스 이동 시 나타나는 값은 수집하지 않았다(`coverage.chartGraphics: false`). 일별기준가는 탭을 처음 열었을 때 제공되는 표의 범위이며, 전체 과거 이력이 아니다. 빈 값과 원문의 ‘조회된 데이터가 없습니다’는 보완하거나 추정하지 않았다.

클래스별 수수료와 수익률이 달라 상품 코드별 파일을 유지했다. 대응표는 클래스까지 이름이 일치하는 항목만 연결한다. 목록에 없는 상품을 비슷한 이름의 다른 상품으로 대체하지 않는다.

## 다시 수집하기

Node.js와 Playwright, Microsoft Edge가 필요하다. Playwright는 수집 환경에만 있으면 되고 앱 의존성으로 추가할 필요는 없다. 설치 위치가 별도라면 `NODE_PATH`에 해당 `node_modules` 경로를 지정한다.

```powershell
node scripts/crawl-wealth.cjs
node scripts/map-wealth.cjs
node scripts/verify-wealth.cjs
npm run build
```

수집기는 완성된 파일을 건너뛰어 중단 후 이어서 실행할 수 있다. 새 기준일로 갱신하려면 기존 자료를 별도로 보관한 뒤 빈 출력 폴더에서 실행한다. `CRAWL_WORKERS`와 `CRAWL_WORKER`로 목록을 분할할 수 있으며, 이번 수집은 3개 작업으로 나누었다. 로그인, 고객정보, 브라우저 사용자 프로필은 사용하지 않는다.

검증기는 대상 파일 누락, 상품 코드와 이름 불일치, 한글 인코딩 오류, 필수 항목과 탭 누락을 검사한다. 수집기가 오류를 출력했다면 검증 결과로 빠진 상품을 확인하고 재실행한다.
